## なぜ自分の持っていないGPUが必要になったか

「SnapSchedule」というアプリを作っています。Mac・iPhone・iPad で、予定のスクリーンショットや PDF を取り込むと、Apple カレンダーの予定にしてくれるアプリです。短いメッセージは簡単で、Apple のオンデバイスモデルが無料で読んでくれます。

問題は学校の時間割でした。1枚の PDF に全学年・全クラスの授業が、5日 × 8時限の表でびっしり並んでいます。小さなオンデバイスモデルでは、そもそも入力に収まりません。

そこで、Mac で動く程度に小さく、こういう表を読むことに特化した自分用のモデルを作ることにしました。ただ、時間割1枚でおよそ2万トークンあるので、学習にはメモリの大きい NVIDIA GPU が必要です。手元の RTX 4070 Super は 12GB、H100 は 80GB。H100 は持っていないので、秒単位で借りることにしました。

## 高火力 DOK とは

高火力 DOK は、さくらインターネットのコンテナ型 GPU クラウドです。Docker イメージを指定すると GPU 上でコンテナが起動し、動いている間だけ秒単位で課金されます。H100 1枚で 1秒あたり 0.28円、1時間でおよそ 1,008円です。サーバーの構築も後片付けも要りません。

タスクが終わるとコンテナは消え、`/opt/artifact`（環境変数 `$SAKURA_ARTIFACT_DIR`）に保存したファイルだけがダウンロード用に残ります。

覚えておくべきはこの一点です。**`/opt/artifact` の外に置いたものは、タスク終了と同時に消えます。**

## 学習データ：自分で作った架空の時間割

本物の時間割は1枚しかなく、データセットにはなりません。代わりに、時間割を自動生成するスクリプトを書きました。科目名・教員名・時限の時刻・レイアウトをランダムに組み合わせ、正解となる予定のリストも同時に出力します。表を作ったのが生成スクリプト自身なので、正解が分かっているわけです。

モデルは画像を見ません。アプリ側で、ページ上の文字とその位置を次のような形で取り出します。

```
y=518 x=352-372 | 数値解析
y=526 x=355-370 | （山田）
```

モデルは、この行の並びと「5S の学生です」のようなメモから、予定のリストを出力することを学習します。学習は Unsloth を使った QLoRA で、ベースは Qwen 2.5 14B です。日本語に強く、量子化すれば 64GB の Mac で余裕を持って動きます。

### 6. Mac で動かす
```bash
cp gguf/*.gguf model.gguf
ollama create snapschedule -f Modelfile
python3 eval.py --model snapschedule --data data/real_test.jsonl --show
```

あとは SnapSchedule の Settings › AI server で、アドレスに `http://localhost:11434/v1`、モデル名に `snapschedule` を入れるだけです。API キーは不要です。
